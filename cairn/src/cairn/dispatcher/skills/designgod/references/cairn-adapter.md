# Cairn 交付适配（仅用户要求时）

本技能是 Codex 的设计前端，不自带 Cairn 服务或导入器。先检查当前可用的 Cairn 工具/API及其真实Schema，不能假装本地Markdown就是已导入的原生草稿。

如果当前宿主提供 Cairn 原生工具：

- `get_context` 读取实际草稿、版本、阶段、基线和修订反馈。恢复已有设计，不另起计划。
- 通过实际可用的设计方式选择接口记录用户明确的快速/教练选择。问题使用可用题卡或自然语言回答接口；精确引用用户答案，不捏造确认。
- 按真实 `save_draft` Schema 保存稳定文档ID、完整正文或受控源路径、decisions、questions和PlannedWork。每个 `spec_refs` 指向真实注册文档ID，可加 `#section`；依赖指向真实任务key。任务验收argv是实现后的检查，不是已通过的证据。
- 原型和实现输入按实际 `materials` 契约登记：仓库相对目标 → 受控源路径。冻结前完成材料准备及冲突检查，不让用户手动搬文件。
- 机械修订直接保存；替换已确认决策遵守当前 `decision_changes` 与已回答问题契约。
- 草稿保存使用服务端返回的新版本，不能覆盖过期版本。文档ID、来源、附件与基线保持一致。
- 以实际候选状态和独立评审状态为准，告知当前界面的真实冻结、送审、确认入口。只在用户已有明确授权且接口允许时执行对应操作；不把自检说成独立评审，不编造UI按钮或审批结果。阶段通过不等于最终发布开发。

没有 Cairn 连接时，完成本地设计文档与实施计划即可，说明尚未写入 Cairn；要接入时需读取其实际契约。不要安装转换器、重建一套黑板、或自行重规划已获批的产品方案。
